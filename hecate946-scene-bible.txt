HECATE946.COM — SCENE BIBLE
Version 1.0

PURPOSE
-------
This document defines the visual language for the house, rooms, halls, and all future
2.5D rendered environments on hecate946.com.

The goal is consistency without over-rendering.

CORE IDEA
---------
A quiet Neoclassical dollhouse rendered with the seriousness of architectural
visualization, but simplified like a physical museum model.

The world should feel:
- authored
- elegant
- restrained
- slightly surreal
- tactile
- architectural
- cohesive
- intentionally sparse

It should NOT feel:
- photoreal for its own sake
- like a game environment
- like an Airbnb interior
- cluttered
- hyper-PBR
- overdecorated
- cinematic in a generic Unreal Engine way


1. ARCHITECTURAL LANGUAGE
-------------------------
Primary style:
Simplified Georgian / Neoclassical manor.

Shared architectural vocabulary:
- strong symmetry where appropriate
- clean rectangular wall divisions
- simple classical trim
- shallow cornices
- tall doors
- restrained arches
- modest pediments
- white or off-white trim
- simple baseboards
- consistent casing profiles
- calm, readable wall surfaces

Every room should feel like it belongs inside the same house.

Do not redesign the architecture from scratch for each room.
Change the room identity through color, material, lighting, and one or two focal objects.

HOUSE LANGUAGE + ROOM IDENTITY

House language:
- same molding family
- same wall thickness logic
- same door proportions
- same trim language
- same camera philosophy
- same material restraint
- same lighting softness

Room identity:
- one dominant color or material idea
- one focal object or interaction
- one secondary object if needed
- one architectural or surreal twist at most


2. ROOM DENSITY
---------------
Rooms should remain deliberately sparse.

Default room formula:

ARCHITECTURAL SHELL
+
ONE DOMINANT OBJECT
+
ONE SECONDARY OBJECT
+
ONE LIGHT FIXTURE
+
OPTIONAL SINGLE STRANGE DETAIL

Examples:
- chess room: checker floor + black table + chess board + pendant + two chairs
- music room: piano + bench + music stand + one wall element
- archive room: shelves + desk + one lamp
- water room: architecture + water + one focal object

Avoid filling empty areas just because they are empty.

DO NOT automatically add:
- plants
- rugs
- books
- cups
- papers
- wall clutter
- excessive paintings
- decorative lamps
- shelves everywhere
- random props

Empty space is part of the composition.


3. DETAIL BUDGET
----------------
Use three levels of detail.

LEVEL 1 — SILHOUETTE DETAILS
Always model these when visible:
- doors
- windows
- tables
- chairs
- lamps
- stairs
- moldings
- major architectural trim
- focal objects

LEVEL 2 — MATERIAL-DEFINING DETAILS
Use selectively:
- chess piece shapes
- broad wood grain
- marble veining
- upholstery seams
- panel joints
- large bevels
- subtle hardware

LEVEL 3 — REALISM DETAILS
Usually omit:
- tiny scratches
- dust buildup
- fingerprints
- screws
- wiring
- microscopic fibers
- chips
- random grime
- tiny wall imperfections

Rule:
If the detail is only interesting when zoomed in, it probably does not belong.


4. MATERIAL PHILOSOPHY
----------------------
Materials should read clearly at a glance.

Prefer:
- matte surfaces
- soft reflections
- broad texture variation
- low-frequency detail
- simple roughness structure
- restrained normal/bump maps

Avoid:
- noisy microtextures
- excessive displacement
- hyper-sharp PBR surfaces
- constant glossy reflections
- texture detail that becomes visual static

WOOD
- broad readable grain
- dark wood should remain dark, not mirror-like
- favor roughness over polished lacquer
- avoid overly orange or saturated wood unless room identity calls for it

MARBLE / STONE
- large soft veins
- restrained contrast
- subtle roughness
- avoid dense tiny cracks

PLASTER / WALLS
- nearly flat
- soft roughness
- extremely subtle variation only
- no obvious procedural noise

METAL
- use sparingly
- simple, convincing reflections
- brushed brass, blackened steel, silver, or muted gold
- avoid chrome unless intentionally focal

FABRIC
- color + roughness first
- subtle weave only if visible
- no need to resolve individual fibers

GLASS
- clean
- simple
- lightly stylized
- avoid overcomplicated caustic-heavy setups unless essential


5. COLOR SYSTEM
---------------
Each room should have one dominant identity.

Examples:
GREEN
- geometry
- chess
- marble
- dark wood
- restrained brass

BLUE
- water
- reflection
- stillness
- cool stone
- soft blue-green light

PURPLE
- fabric
- softness
- low light
- dark neutrals
- muted violet

ORANGE
- wood
- archive
- warmth
- amber light
- parchment / paper tones

Use neutrals to support the room color.
Do not let every object compete for attention.


6. LIGHTING
-----------
Lighting should feel soft, architectural, and intentional.

Default lighting model:

ONE PRIMARY ARCHITECTURAL LIGHT
+
ONE BROAD ENVIRONMENT / FILL
+
OPTIONAL PRACTICAL FIXTURE

Use large light sources whenever possible.

Prefer:
- soft shadows
- broad gradients
- gentle falloff
- restrained contrast
- practical lights supported by invisible area lights when needed

Avoid:
- fifteen small realism lights
- harsh razor shadows
- excessive bloom
- generic cinematic rim lights
- strong volumetric fog everywhere
- neon accents without purpose

The practical light may be visible.
The light actually shaping the room does not have to be.


7. CAMERA LANGUAGE
------------------
The camera is one of the strongest tools for visual consistency.

Use three camera families.

A. ESTABLISHING VIEW
- nearly straight-on
- architectural
- balanced
- calm
- minimal distortion
- used to understand the room

B. OBJECT VIEW
- closer composition
- focused on the interactive object
- still controlled and clean
- no dramatic wide-angle distortion

C. TRANSITIONAL VIEW
- doorway
- corridor
- stair
- architectural detail
- used to move between spatial ideas

Default lens philosophy:
- favor roughly 50–85mm equivalent perspective
- avoid 18–24mm game-camera views
- use long enough focal lengths to keep geometry calm
- use orthographic only when deliberately needed

Every shot should look composed, not merely navigable.


8. COMPOSITION
--------------
Treat every render like a designed still image.

Prioritize:
1. silhouette
2. focal object
3. negative space
4. light
5. material
6. detail

The room must still work when viewed as a thumbnail.

If the composition depends on tiny details, simplify it.


9. 2.5D PHILOSOPHY
------------------
Blender owns the appearance.
The browser owns interaction.

Do not recreate Blender lighting or materials in the browser.

Default pipeline:

BLENDER
author geometry + material + lighting + camera + hotspots

↓

CYCLES
render final view

↓

EXPORT
image + interaction metadata

↓

WEBSITE
crossfade + hover + preload + subtle parallax

Runtime 3D is not required for normal room navigation.


10. 2.5D DEPTH
--------------
Most views can be one flattened render.

Important views may be split into:

- background
- midground
- foreground
- optional lighting overlay
- optional atmospheric overlay

Use very subtle cursor parallax.

Suggested feel:
- background: 1–2 px
- midground: 3–5 px
- foreground: 5–9 px

Parallax should be felt more than noticed.

Do not make the scene wobble or behave like a 3D demo.


11. MOTION
----------
Motion should be restrained.

Allowed:
- crossfades
- tiny parallax
- slow window glow
- curtain movement
- dust
- rain
- water movement
- soft reflection movement
- subtle environmental animation

Avoid:
- constant camera drift
- idle rotations
- exaggerated hover zooms
- game-like WASD movement
- large camera sway
- distracting looping animations

The environment may feel alive, but never restless.


12. HOTSPOTS / INTERACTION
--------------------------
Clickable areas should be authored in Blender whenever possible.

Use invisible hotspot objects in the Blender scene.

The exporter should project those objects through the active camera and generate
browser-space bounds automatically.

Never manually maintain HTML coordinates if Blender can own the source of truth.

Hotspots should:
- correspond to obvious visual objects
- be large enough to use comfortably
- never overlap each other
- not cover unrelated parts of the image
- reveal a minimal label on hover

Labels should be quiet and temporary.


13. SHARED BLENDER STYLE SYSTEM
-------------------------------
Future room builders should share common helpers.

Recommended structure:

blender/style/
    architecture.py
    materials.py
    lighting.py
    cameras.py
    render.py

Reusable functions should eventually include:

- make_wall_material()
- make_dark_wood()
- make_light_wood()
- make_brushed_brass()
- make_blackened_steel()
- make_marble()
- make_fabric()
- add_room_molding()
- add_standard_door()
- add_standard_window()
- add_soft_key_light()
- add_environment_fill()
- configure_room_camera()
- configure_cycles()

Global style changes should happen once, not room by room.


14. RENDER PHILOSOPHY
---------------------
Use Cycles for final renders.

Goal:
polished architectural-model rendering, not photorealistic simulation.

Prioritize:
- clean anti-aliasing
- stable lighting
- readable materials
- soft shadow quality
- controlled denoising
- consistent exposure
- consistent color management

Do not spend render time on invisible microdetail.

A room should look intentional before render settings become expensive.


15. ROOM DESIGN TEMPLATE
------------------------
For every new room, define the following before modeling.

ROOM NAME:
ROOM COLOR:
ROOM PURPOSE:
PRIMARY MATERIAL IDEA:
PRIMARY OBJECT:
SECONDARY OBJECT:
LIGHT FIXTURE:
ARCHITECTURAL VARIATION:
SURREAL ELEMENT:
ESTABLISHING CAMERA:
OBJECT CAMERA:
TRANSITION CAMERA:
PRIMARY HOTSPOT:
SECONDARY HOTSPOT:
TARGET PAGES / VIEWS:

Then ask:

- What is the single visual thesis?
- What can be removed?
- Does this room still belong to the house?
- Is anything included only because the space looked empty?


16. QUALITY CHECKLIST
---------------------
Before approving any room:

ARCHITECTURE
[ ] Same house language
[ ] Trim/molding consistent
[ ] Door/window proportions consistent
[ ] No unnecessary ornament

COMPOSITION
[ ] One clear focal point
[ ] Strong negative space
[ ] Works at thumbnail size
[ ] Camera does not feel like a game camera

MATERIALS
[ ] Materials read clearly
[ ] No noisy microdetail
[ ] Reflections are restrained
[ ] Wood/marble/fabric do not feel over-rendered

LIGHTING
[ ] Soft primary light
[ ] Broad fill
[ ] Practical fixtures are believable
[ ] No gratuitous bloom/fog/rim light

PROPS
[ ] Every prop has a reason
[ ] Room is not cluttered
[ ] No filler decorations

2.5D
[ ] Hotspots correspond to visible objects
[ ] Hotspots do not overlap
[ ] Adjacent views can preload
[ ] Crossfade feels natural
[ ] Parallax is subtle

COHESION
[ ] Could this room physically belong inside the exterior house?
[ ] Does it look like the same artist built it?
[ ] Is the room identity clear without breaking the house language?


17. FINAL RULE
--------------
When unsure, simplify.

The site should feel like a carefully built architectural miniature that slowly becomes
stranger as the user explores it.

Physical → architectural → symbolic → graph → source.

The house is the emotional representation of the site.
The graph is the structural representation of the site.
HTML mode is the raw informational representation.

All three should describe the same underlying world.
